# setodaCTF 問題 解説：pcapからホスト名を特定

## 問題概要
`.pcap` ファイルを読み込み、フラグを見つける。
指示：ホスト名をフラグ形式で答える。英字はすべて小文字。
例：ホスト名が `host.example.com` なら `flag{host.example.com}`。

## pcapとは
- **pcap（packet capture）**：ネットワークを流れた通信（パケット）をそのまま記録したファイル。誰が何を送受信したかが全部入っている。
- 解析ツール：**Wireshark**（GUI）、**tcpdump / tshark**（CLI）。

## 解法の流れ

### 1. まず文字列を確認
```bash
strings host.pcap
```
→ HTTP通信（暗号化されていない平文）が記録されていた。

### 2. 通信の中身を確認
- リクエスト：`GET / HTTP/1.1`
- 応答：`200 OK`（「May I help you?」というHTML）
- 全10パケット。認証情報や隠しヘッダは無く、ごく普通のWebアクセス1回分。

### 3. ホスト名を特定
HTTPリクエストの **Host ヘッダ** にアクセス先が明記されていた。
```
Host: ctf.setodanote.net
```
- **Hostヘッダ**：HTTPリクエストで「どのサイトにアクセスしたいか」を示す部分。まさにホスト名。

### 4. フラグ形式に整える
問題文の指示通り、ホスト名を小文字で `flag{ }` に入れる。
```
flag{ctf.setodanote.net}
```

## 補足：通信ログの各パケットの役割
1回のWebアクセスでも、前後に準備・確認の通信がある。

| 役割 | 内容 |
|------|------|
| 3ウェイハンドシェイク（SYN/SYN-ACK/ACK） | 通信開始前の「あいさつ」3往復。TCPの決まり |
| GETリクエスト | 「ページください」 |
| ACK | 「受け取りました」の確認 |
| 200 OK 応答 | ページの中身（HTML）を返す |

- **TCP**：データを確実に届ける仕組み。宛先・順番・再送を管理するだけで、中身が何かは問わない。
- 認証情報（ID/パスワード）はTCPではなく、その上を流れるHTTPの `Authorization` ヘッダやPOSTデータに入る。今回は単純なGETなので認証情報は無し。

## ポイント
- pcap問題ではまず `strings` で平文を確認するのが早い。
- HTTPの `Host` ヘッダにアクセス先ホスト名がそのまま残る。
- Wiresharkの `Follow → HTTP Stream` や `Export Objects → HTTP` で通信内容を読みやすく取り出せる。
