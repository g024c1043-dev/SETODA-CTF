# CTF解説: マジックナンバーでファイルを識別する問題

## 問題概要
フォルダ内に様々なファイルが入っており、**マジックナンバー**（ファイル先頭の目印バイト）を調べて、拡張子が偽装されたファイルや目的のファイル形式を特定する。

## 前提知識

| 用語 | 説明 |
|------|------|
| マジックナンバー | ファイル先頭の数バイトにある、ファイル種類を示す固有の目印。拡張子を偽装しても中身の本当の形式がわかる |
| バイナリ読み込み (`'rb'`) | ファイルをバイト列として読む方法 |
| `.hex()` | バイト列を16進文字列に変換する。スペースなし・小文字で並ぶ（例: `89504e47`） |
| glob | パターンに合うファイル名一覧を取得。`/*` でフォルダ内すべて |
| `os.path.isfile()` | パスがファイルなら True。フォルダを除外できる |

## 代表的なマジックナンバー（先頭バイト）

| 形式 | 16進 |
|------|------|
| PNG | `89504e47` |
| JPEG | `ffd8ffe0` |
| PDF | `25504446`（`%PDF`） |
| ZIP | `504b`（`PK`） |
| RAR | `52617221`（`Rar!`） |

## 解法の流れ

1. `glob` でフォルダ内の全ファイルパスを取得
2. `os.path.isfile()` でフォルダ（`$Recycle.Bin` 等）を除外
3. 各ファイルを `'rb'` で開き、先頭を `read(16).hex()` で取得
4. `startswith()` でマジックナンバーと照合し振り分け

## つまずきポイント

- **`.hex()` の形式**: スペースは入らない。`89 50 4e 47` ではなく `89504e47` で書く
- **`in` と `startswith()` の違い**: 「先頭が一致するか」を見たいので `startswith()` を使う。`in` は「含まれるか」なので誤判定の元
- **リスト初期化の位置**: `bi1 = []` はループの**前**で1回だけ。中に置くと毎回リセットされる
- **権限エラー**: `$Recycle.Bin` など読めない特殊フォルダは `os.path.isfile()` で除外

## 完成コード

```python
import glob
import os

bi1, bi2, bi3 = [], [], []   # ループの前で初期化

for i in glob.glob('./magic_number/*'):
    if os.path.isfile(i):
        with open(i, 'rb') as f:
            binaly = f.read(16).hex()
        if binaly.startswith('89504e47'):      # PNG
            bi1.append(i)
        elif binaly.startswith('52617221'):    # RAR
            bi2.append(i)
        elif binaly.startswith('ffd8ffe0'):    # JPEG
            bi3.append(i)

print(bi1, bi2, bi3)
```

## ポイントまとめ
- ファイルの正体は拡張子ではなく**先頭バイト（マジックナンバー）**で判断する
- `.hex()` はスペースなし小文字 → 照合パターンも同じ形式で書く
- 先頭一致の判定は `startswith()`
- `file` コマンドや `xxd` でも手軽に確認できる
