# setodaCTF Web問題 解説：ディレクトリインデックス

## 問題概要
作成中のサイトに不備があり、機密情報が漏れている。サイトにアクセスして隠されたフラグを見つける。

## 解法の流れ

### 1. ヒントの発見
ページのソースコードを表示すると、HTMLコメント内に手がかりがあった。

```html
<!-- Webserver directory index? -->
```

- **HTMLコメント** `<!-- -->`：ブラウザには表示されないメモ書き。開発中のメモが残ってしまうことがある。

### 2. ディレクトリインデックスとは
フォルダにアクセスしたとき、中身のファイル一覧がそのまま表示されてしまう状態のこと。

- 通常、フォルダにアクセスすると `index.html`（そのフォルダの玄関ページ）が表示される。
- `index.html` が**無く**、サーバー設定でインデックス表示が**オン**だと、フォルダ内のファイル一覧が丸見えになる。

### 3. index.html の役割
- **ホーム（トップページ）**：`example.com/` にアクセスすると自動で `index.html` が開く。
- **中身を隠す**：これがあるとフォルダの一覧表示を防げる。
- たとえるなら「玄関の受付係」。受付が居れば中は見られないが、不在だと部屋が丸見え。

### 4. 攻略
画像パス `images/` にそのままアクセス。

```
サイトURL/images/
```

`images/` フォルダに `index.html` が無かったため、ファイル一覧が表示され、機密ファイルが見つかった。

## ポイントまとめ
| 項目 | 内容 |
|------|------|
| 脆弱性 | ディレクトリインデックス（ディレクトリリスティング） |
| 原因 | フォルダに `index.html` が無く、サーバーの一覧表示がオン |
| ヒント | HTMLコメント `Webserver directory index?` |
| 対策 | 各フォルダに `index.html` を置く／サーバー設定で一覧表示をオフにする |

## 学び
- ソースコードのコメントには開発の痕跡が残りやすい。
- 公開フォルダの設定ミスは情報漏洩に直結する。
